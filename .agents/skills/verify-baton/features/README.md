# Baton verification feature map

Use these files with `../SKILL.md`. Each journey is written for an agent that has never seen baton.

| Feature | Surface | Proof |
|---|---|---|
| Doctor | CLI | `baton doctor` next action, six providers, readiness, database count |
| TUI status | TUI | `/status` shows thread, phase, queue, and adapter lifecycle |
| Queued follow-ups | TUI | `/queue` opens the queue; Enter sends, `e` edits, `d` deletes, `c` twice clears, and Ctrl+Up/Ctrl+Down reorder; every action persists through the store |
| Slash choices | TUI | typing a command argument lists valid choices or its syntax, filters them, and completes with Tab or Enter; `slash_sweep.py` runs 57 cases across 51 of the 52 registered commands plus argument variants, and `slash_probe.py` covers the remaining `/quit` path |
| Settings | TUI | `/settings` writes global default mode and bell choices, shows the selected category's options, and labels harness rows read-only |
| Auth billing | TUI | `/auth` lists every harness with subscription and API rows, marks the current mode, names the key variable or `missing`, applies a keyed choice, and keeps the picker open on a missing key or malformed config |
| Login | TUI | `/login` lists every harness with the command it runs, suspends the TUI, runs the harness login, then resumes and reports the result |
| Approval choices | TUI | an approval lists the provider's own choices, arrows and Enter send the selected id, y/a/n keep the standard shortcuts, and a child request names the child thread |
| Provider questions | TUI | Codex `requestUserInput` and Grok `x.ai/ask_user_question` walk each question, answer an option or a custom Other text, mask secret input, and batch the native answers map |
| Worker questions list | TUI | `/questions` lists open worker questions and opens the worker thread to answer |
| Roles | TUI and CLI | `/roles` shows the four resolved role rows and detail; `baton roles --json` also returns effort, prompt source/path, and parsed hook declarations |
| Skills | TUI | `/skills` lists Claude and Codex skills, marks project and global copies, scrolls past eight rows, inserts the source-specific invocation on Enter, installs a global copy on `i`, updates the project copy on `u`, and removes a project copy on `d` after confirmation |
| Status next action | CLI | `baton status` and `--json` answer what to do now; a directory with no threads exits 0 with a null-thread JSON shape and `start a thread with baton` |
| Model catalog | TUI | `/model` merges the live list, the last recorded full list, and the known catalog; a short or failed probe keeps the older models |
| Provider readiness | CLI and TUI | doctor summarizes ready/missing; pickers mark missing harnesses |
| Default provider | CLI and TUI | new work starts on an installed harness, with an explicit override |
| Recent thread hint | TUI | a new session points at existing threads in the folder |
| Usage report | TUI | `/usage` picks this thread or all threads, then totals or a day/model/provider grouping, and shows a scrollable report |
| Terminal capabilities | TUI | `NO_COLOR` or `TERM=dumb` renders without palette colors, and a non-interactive stdin or stdout exits with a message that names `baton exec` as the script path |
| Plan review | TUI | `/plan` shows harness-reported item, markdown, and file plans with explanation, status, priority, and file URI in a scrollable read-only overlay; an empty state names why there is no plan |
| Thread tabs | TUI | every opened thread gets one tab above the transcript, Alt+1 through Alt+9 switch to it, the active tab is highlighted, an unsaved draft and its composer text survive a switch, a live turn keeps streaming in its tab with a `*` marker, a queued follow-up starts when that background turn finishes unless a handoff preview is needed, and archiving closes the tab; `/pane` shows one read-only second pane with the other thread's tail and live state, Alt+W swaps focus, and Alt+[ or Alt+] resizes the split; `tabs_probe.py`, `background_turn_probe.py`, and `pane_probe.py` prove the strip, background stream, and pane swap in a real PTY |
| Attention inbox | TUI | `/inbox` lists failed, unverified, interrupted, needs-input, and queued work and opens the selected thread |
| Thread pins | TUI; CLI read | `/pin` toggles a durable pin, Ctrl+Up/Ctrl+Down or `/pin move` orders pinned threads, pinned rows sort first, and `baton threads --json` exposes `pinned` and `pin_order_key` |
| File navigation | TUI; CLI | `/files [--ignored]` inserts a selected project path or `path:line` and warns when ignored files are included; Ctrl+O launches that target or a selected `/grep` match in `VISUAL` or `EDITOR`; `/grep` and `baton grep` search file contents with sorted previews; `baton files` ranks project paths with ripgrep or git; and `baton open` launches the editor with `-C`-directory containment |
| Shell command | TUI | a `!` line runs one command in the thread cwd, captures stdout and stderr, sanitizes and caps the output, shows the exit code, and is not sent to the harness |
| Command palette | TUI | Ctrl+K filters built-in actions, threads, and recent files; Enter runs the action, opens the thread, or inserts the path; an open picker keeps the key |
| Prompt snippets | TUI; CLI read | `/snippets` lists each command under `~/.baton/commands`, `~/.claude/commands`, `.baton/commands`, and `.claude/commands`, with project files shadowing user files and `.baton` shadowing `.claude`; `/snippets add [--global] <name> <template>` writes a validated project or user `.baton` file and refreshes the registry; `/snippets remove [--global] <name>` deletes only that `.baton` file and never a `.claude` one; a snippet whose body starts with `!` runs through the shell path after `{{args}}` and `{{cwd}}` expand; each change writes a `tui` audit row |
| Composer file mentions | TUI | typing `@path` offers matching directories with a trailing slash, then ranked project files; Tab or Enter replaces only the mention token, and ordinary text and addresses never start an index load |
| Shell completions | CLI | `baton completions <shell>` generates from the clap command graph and handles a broken pipe |
| Issue tasks | CLI and TUI | `/task [number]` or `baton task <number>` reads an open issue from `origin` and creates a linked worktree; no number opens an issue picker |
| Schedules | CLI, host, and TUI | `baton schedule add/list/pause/resume/remove` stores UTC cron schedules, and `baton serve` claims each due tick once, audits it, and posts into the thread; `/schedule` lists rows, toggles pause, removes after a second press, and adds one with a thread, cron, and prompt form; a long outage coalesces to one run, and an invalid expression is deferred an hour without a run record; the schedule CLI and serve tests plus the `schedule-claim-state-machine` gate with an `ignorepaused` mutant prove it |
| Side chat | TUI | `/btw` forks the thread, marks it as a side chat of the source, opens it, and prefills an optional prompt; the source is unchanged |
| Fork | CLI | `baton fork --json` creates a new thread without changing the source |
| Native fork | CLI | `baton fork --native` attaches a Codex or OpenCode native session to the fork |
| Native rewind | CLI | `baton rewind --native` truncates Codex or OpenCode history and keeps the session |
| Archive | TUI | `/archive` hides a thread from the default lists and the inbox and starts a new thread when the open one is archived; a running turn blocks it; `/threads all` marks archived rows; opening one or `/unarchive` restores it; `baton threads --all` reports `archived_at` |
| Snooze | TUI | `/snooze` opens a picker with `off`, `1h`, `4h`, `tomorrow`, and `week` and shows each wake time; `/threads` marks a snoozed thread; `/inbox` hides it until a new failure or question after the snooze, or until the wake time passes |
| Rate limits | TUI | `/limits` asks Codex for a live snapshot, then shows the primary and secondary windows with used percent, window length, reset time, plan, and credits; each other harness shows an explicit unknown line, and a failed read names its reason |
| Changes view | TUI | `/changes` opens every diff in the thread in one scrollable view, with `turn N` headings, `[` and `]` jumps, `/changes <turn>` filtering, and a clear empty state |
| Diff expansion | TUI | a diff longer than twelve rows collapses with `… N more lines · ctrl+t expand`; a multi-file diff keeps every path and its counts, spilling to `… N more files` only when paths alone fill the rows; Ctrl+T expands every long diff inline and swaps the hint to `ctrl+t collapse`; short diffs are unchanged; `scripts/diff_expand_probe.py` proves the collapse, expand, and recollapse in the real TUI against a two-file turn-written diff |
| Review | TUI | `/review` shows the turn diff, `/` finds text or a path, saves a line note, and leaves it unsent |
| TUI native rewind | TUI | `/rewind --native` truncates the provider and store history and prefills the message |
| Retry | TUI | `/retry` lists failed or unverified turns and submits the chosen prompt as a new turn |
| Greeting | TUI | `hi` in default orchestrate mode answers directly, with no planner run |
| MCP | CLI | `baton mcp` handshakes, lists 15 tools including agents, and answers status, turns, threads, agents, and doctor over stdio. `--http <addr> --token-file <path>` serves the same tools over POST /mcp with a 0600 bearer-token file, a loopback default, and `--trusted-overlay` for a plain-HTTP non-loopback bind. `--read-only` hides `baton_fork` and refuses queue clearing while read tools remain; repeatable `--allow-tool` exposes only the named tools. `--tls-cert` and `--tls-key` serve HTTPS with a 0600 key; a non-loopback bind needs TLS or `--trusted-overlay`. On Unix, SIGHUP reloads the token file; an invalid file keeps the old token. Proof: `mcp::tests::initialize_and_list_tools`, `mcp::tests::token_file_requires_a_private_regular_file`, `mcp::tests::http_requires_a_bearer_and_answers_initialize`, `mcp::tests::read_only_scope_hides_fork_and_refuses_mutations`, `mcp::tests::allowlist_limits_the_callable_tools`, `mcp::tests::known_tool_names_match_the_tool_list`, `mcp::tests::tls_identity_requires_a_private_key`, `mcp::tests::tls_identity_rejects_invalid_pem`, `mcp::tests::tls_bind_policy_requires_encryption_or_an_overlay`, `mcp::tests::tls_serves_initialize_after_a_handshake`, `mcp::tests::token_reload_keeps_the_old_value_when_the_file_is_invalid`, and `cli::tests::mcp_http_requires_a_token_file` |
| Host pairing | CLI | at the host terminal, `pair [--ceiling <mode>]` mints a grant with read and operate defaults, prints a `baton://local#grant=...&secret=...` URL, and the grant answers `status` over the local socket. The ceiling is `default` unless `plan` or `acceptEdits` is chosen; bypass is never grantable. Absolute `--project` roots restrict the grant, or omit them to allow every project. Proof: `serve::tests::pair_parses_labels_scopes_and_expiry`, `grants::tests::project_allowlists_accept_children_and_reject_siblings`, and the `submit-ceiling-state-machine` gate |
| Host attach | CLI | `baton attach --url <url> [--json]` validates the pairing URL, sends one read-only `status` request over the local socket, and prints the host scope, thread count, and running turn count without starting a second engine. `--thread <id>` reads that thread's status, `--messages` pages its stored messages from a resume cursor, and `--follow` polls until the thread is idle, and `--submit <text>` starts a turn through the engine for that thread's project; the host starts or reuses one engine per project. Proof: `attach::tests::status_response_is_typed`, `attach::tests::message_response_is_typed_and_rejects_a_cursor_behind_its_rows`, `serve::tests::protocol_answers_ping_status_claim_info_and_errors`, `store::tests::messages_after_a_cursor_page_forward_without_repeats`, `tests/serve.rs::serve_stdin_pair_and_attach_use_the_socket`, and `tests/serve.rs::serve_socket_submit_runs_a_turn_through_the_host_engine`; a thread above the grant ceiling is refused in `serve::tests::submit_refuses_a_thread_above_the_grant_ceiling`; a thread or interaction outside the grant's project allowlist is refused in `serve::tests::submit_refuses_a_project_outside_the_grant_allowlist`, `serve::tests::approvals_require_approve_scope_and_answer_once`, and `serve::tests::questions_require_approve_scope_and_answer_once`; the host starts one engine per project and routes the two-project submit through both in `tests/serve.rs::serve_socket_submit_runs_a_turn_through_the_host_engine`, with pool routing covered by `serve::tests::pool_interactions_follow_the_project_allowlist` and the `engine-pool-state-machine` gate; remote approvals are listed and answered through `serve::tests::approvals_require_approve_scope_and_answer_once` and the `remote-approval-state-machine` gate, with client parsing in `attach::tests::approvals_response_is_typed_and_text_is_sanitized` and `attach::tests::answer_response_is_typed_and_requires_answered`; remote questions are listed and answered through `serve::tests::questions_require_approve_scope_and_answer_once` and the `remote-question-state-machine` gate, with client parsing in `attach::tests::questions_response_is_typed_and_text_is_sanitized` and `attach::tests::question_answer_response_is_typed_and_requires_answered`; the idempotency key replay is covered by `store::tests::idempotency_claims_replay_and_can_be_forgotten` and the submit test's second attach with the same key |
| Audit log | CLI | `baton audit list [--limit N] [--json]` shows append-only grant, MCP queue clear, and MCP fork events with actor, environment, action, scope, confirmation, payload digest, result, and retention; the table rejects updates and deletes, and each mutation commits with its audit row |
| Antigravity | CLI | `agy acp` completes one turn with the ICA key and custom base URL |
| Harness matrix | CLI | Codex, Claude, Cursor, Grok, OpenCode, and Antigravity are checked for a live ICA turn or an explicit external account block |
| Output sanitization | CLI and TUI | Control sequences are replaced before `exec` stdout and the transcript; unit proof only |
| Activity | TUI and CLI | `/activity` and `baton activity --json` index every turn's tools, diff, and usage |
| Subagent calls | TUI and CLI | `/agents` lists live and persisted subagent calls with running, done, failed, or unknown status; `baton agents -t <id>` and `baton_agents` expose the persisted rows |
| Memory files | TUI | `/memory` lists Claude and Codex instruction files, opens or creates them in the editor, and toggles Claude auto-memory; existing `CLAUDE.md` files between the repository identity root and the working directory appear as parent instructions, outermost first |
| Git status, commit, push, checks, pull request, review, and merge | TUI | `/git` inspects the repository, confirms exact commit plans, pushes a chosen remote without force, lists the current pull request's `gh` checks, opens a pull request after a title and body preview, approves, requests changes on, or comments on the current pull request after rechecking the head, and merges it with squash, merge commit, or rebase after the same recheck |
| Grok | CLI | `grok agent stdio` completes a turn on the ICA endpoint |
| Cursor | CLI | `cursor-agent acp` gives the login hint and rejects a custom endpoint |
| Process registry | CLI | `baton ps --json` returns a stable schema and no false live processes |
| Orchestration | CLI | `baton orchestrate` creates worktrees, runs harnesses, and records runs |
| Orchestrate stream | CLI | `--stream-json` emits plan, worker, and result JSONL rows |
| Spawn | CLI | `baton spawn` runs one worker in a worktree and returns JSON |
| Exec stream | CLI | `baton exec --stream-json` emits parseable JSONL and a final result row |
| Adapter lifecycle | TUI | `/status` shows one state and owner pair per adapter |
| Missing harness | CLI and TUI | `exec`, `/switch`, and the banner name the binary and the next step |
| Installers | Shell and PowerShell | `ci/installer-selftest.sh` selects the Linux asset, verifies its SHA-256, and rejects a corrupted archive |

Start with the feature touched by the change. One real journey is enough for a smoke proof; the map exists so a broader change can cover the rest.
